# Bifrost E2E User Story — Minimal Viable Slice

## The Scenario

Priya is a senior backend engineer who joined the delivery team (DLVR) three months ago. The team owns four microservices — `webhook-api`, `dispatcher`, `signing-keys`, and `usage-metering` — spread across separate repositories. She has been asked to add a new webhook retry policy and to support signing key rotation, so she needs to understand which components `webhook-api` exposes to the rest of the platform: specifically which REST endpoints exist, what the `DeliveryService` class does, and what downstream services it calls. The team has no unified documentation. There is a Confluence page from 2023 that is known to be wrong.

Priya has Bifrost running locally. She wants to register the `webhook-api` repo, let the extraction agent analyze it, then ask a natural language question and get a grounded, sourced answer she can trust — with explicit confidence labels so she knows what the agent is certain about versus what it inferred from code.

## Step 2: Register a Repository

**Request:**

```
POST /api/v1/repos
Content-Type: application/json
Authorization: Bearer bft_<admin token>

{
  "name": "webhook-api",
  "clone_url": "https://github.com/acmeco/webhook-api.git",
  "domain_id": "domain_delivery",
  "default_branch": "main"
}
```

```json

  "data": {
    "id": "repo_abc123",
    "name": "webhook-api",
    "clone_url": "https://github.com/acmeco/webhook-api.git",

    "default_branch": "main",
    "status": "registered",

  },
  "metadata": {
    "request_id": "req_9kR2pq",

  }

```

**Side effect:** Registration triggers minimum T0+ bootstrap in the background — clones the repo to `~/.bifrost/repos/repo_abc123/`, parses `package.json` and `README.md` (no LLM calls), and writes structural mappings. This takes ~30 seconds and unblocks basic keyword-to-repo routing before full LLM extraction begins.

**Equivalent CLI command:**

```
bifrost repos add https://github.com/acmeco/webhook-api.git \
  --name webhook-api \
  --domain delivery
```
